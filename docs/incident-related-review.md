# Related incident review on creation

Both manual and confirmed-source creation run the same server-side suggestion check inside the creation transaction, after checking the active Security Officer and (for sources) the existing conversion guard.

The check reads at most 200 newest records whose detected_at is within seven days on either side of the proposed detection time (created_at fallback for historical null detection times). It includes all creation methods and statuses. At most five suggestions are returned, preferring non-closed incidents. Titles are normalized for case/diacritics and compared by meaningful token overlap; descriptions are not scanned. There are no extra per-keystroke requests or user-operated filters.

HTTP 409 INCIDENT_RELATED_REVIEW_REQUIRED returns error.details.items: id, incidentCode, title, status, detectedAt, reason. No incident is created or finding claimed. The client preserves the submitted form. The officer can inspect an existing incident, return to edit, or create separately with a 10–2000 character separateReason and reviewedIncidentIds (maximum five UUIDs). Every currently suggested ID must be reviewed; a new candidate requires review again. Overrides are recorded through auditWriter as INCIDENT_CREATED_SEPARATELY in the creation transaction. An audit failure rolls back creation.

This heuristic is intentionally advisory and bounded. Reworded titles, older records beyond the candidate cap, and incidents outside the time window can be missed. Shared words can produce false positives. Current creation forms do not select assets or accounts, so no reliable asset/account matching is claimed. No new schema or indexes are introduced; the existing schema lacks a detection-time index, so the database may still scan records to apply the date filter. Measure query plans before scaling. This does not provide semantic uniqueness, a request idempotency guarantee, automatic incident merging, or a new link-finding workflow. Existing detail/evidence/link workflows remain unchanged. Concurrent manual requests may both pass before either commits.
